# 틈 · cutcut

사진을 먼저 추가하고, 각 사진을 1~4칸으로 나누어 이어지는 사진을 만드는 정적 웹앱입니다. 사진마다 하나의 구도를 공유하므로 같은 사진의 칸들을 따로 맞출 필요가 없습니다. 전체 출력은 최대 4칸입니다.

## 실행

`index.html`을 브라우저에서 열면 설치 없이 사용할 수 있습니다. 로컬 서버가 필요하면 Node.js에서 `npm start`를 실행하고 http://127.0.0.1:4173 에 접속하세요. 외부 패키지는 필요 없습니다.

## 사용법

1. **사진 추가**에서 PNG, JPG, WEBP 사진을 고르거나 캔버스에 놓습니다. 여러 파일을 한 번에 선택할 수 있습니다. 파일 선택기가 전달한 순서대로 추가되며 각 사진은 처음에 1칸입니다.
2. 사진 목록에서 각 사진을 몇 칸으로 나눌지 선택합니다. A 2칸 + B 2칸은 A가 1–2번, B가 3–4번이 됩니다. 한 사진을 4칸으로 나누거나 A 3칸 + B 1칸도 가능합니다. 사진을 더 추가하려면 총 칸 수가 4 미만이어야 합니다.
3. 영역을 드래그해 옮기거나 위·아래의 산호색 경계를 드래그해 높이를 바꿉니다. 방향키는 1px, Shift + 방향키는 10px 단위로 움직입니다.
4. **같은 간격으로 함께 이동**은 선택한 사진의 칸들을 함께 이동합니다. **칸마다 자유롭게 이동**은 각 영역을 독립적으로 조절합니다. 확대·위치 슬라이더와 폭·높이 설정은 선택한 사진의 모든 칸에 함께 적용됩니다. 다른 사진의 구도는 바뀌지 않습니다. 사진별 출력 크기는 다를 수 있습니다.
5. 사진 목록의 **앞으로 / 뒤로**로 순서를 바꾸면 연결된 칸도 함께 이동합니다. 사진별 확대·위치·크기 설정은 유지됩니다. **선택한 사진 교체**는 해당 묶음 전체의 사진을 교체하고 구도를 초기화하며 칸 수는 유지합니다. 사진을 삭제하면 뒤의 칸 번호가 자동으로 당겨집니다.
6. PNG 또는 JPG로 선택한 칸을 저장하거나, 모든 사진의 분할 결과를 ZIP으로 저장합니다. 파일명 앞의 01, 02… 순서는 사진 목록과 이어보기 순서를 따릅니다.

### 확대와 자르기 영역

작업 캔버스의 원본 사진은 확대하거나 이동하지 않습니다. **확대 200%**는 현재 자르기 영역의 폭·높이를 100%일 때의 절반으로 줄여, 더 좁은 부분을 골라 보는 기능입니다. 같은 사진의 칸과 간격은 하나의 묶음으로 줄어듭니다. 위치 슬라이더는 이 자르기 묶음을 원본 위에서 이동합니다.

확대 후에도 위·아래 경계를 원본의 맨 위·맨 아래까지 늘릴 수 있습니다. 폭·높이 입력값은 실제로 자르는 원본 픽셀 수이며, 1× 출력은 이 크기로 저장됩니다. 출력 픽셀을 늘리려면 저장의 **출력 배율**을 사용하세요. 축소할 때는 원본 안에 들어오는 범위까지만 자르기 영역이 커집니다. **구도 초기화**와 **원본에 맞춰 다시 배치**는 100%로 돌아갑니다.

## 간격 보정 방식

이어보기는 가로 한 줄에 원본 비율로 조각을 보여주는 참고용 화면입니다. X의 모든 앱 버전, 기기, 화면 크기, 게시 위치의 레이아웃을 보장하지 않습니다. 4px 기본값은 조정 가능한 시작값이며 X의 공식 규격이 아닙니다.

간격 값은 표시 높이 480px 기준입니다. 실제 미리보기는 공간에 맞춰 높이 240px(모바일 200px)로 축소되므로 틈도 같은 비율로 작아집니다.

- **보정 켜기:** 원본에서 `간격 × 자르기 높이 ÷ 480`픽셀을 칸 사이마다 건너뜁니다. 사진에 흰 여백을 넣는 방식이 아닙니다.
- **보정 끄기:** 연결 모드에서는 사진을 인접한 영역으로 자릅니다. 이어보기 간격은 비교용으로 남습니다.
- **자유 이동:** 각 칸의 수동 위치를 우선합니다. 보정 스위치가 자유 배치를 덮어쓰지 않습니다. 일정한 간격 보정이 필요하면 연결 모드로 바꾸세요.
- 폭, 높이, 간격 변경 시 연결 모드의 영역은 중앙에 다시 배치됩니다. 위·아래 경계 조절은 현재 위치를 최대한 유지합니다.

## 이미지 처리 및 제한

사진은 Canvas로 기기 내에서 처리됩니다. 사진 업로드 서버, 분석 서비스, 외부 폰트/CDN 요청이 없습니다. 새로고침하면 작업은 사라집니다. 예제 패턴은 앱 안에서 생성하는 정렬 확인용 도형입니다.

입력은 최대 30MB / 4천만 화소입니다. 출력은 한 장당 최대 2,400만 화소, 한 변 최대 16,000px입니다. 기기의 메모리에 따라 더 작은 크기가 필요할 수 있습니다. 2×는 보간 확대이며 새로운 디테일을 복원하지 않습니다. PNG는 투명도를 유지하고 JPG의 투명 영역은 흰색으로 저장됩니다. 애니메이션 WebP는 정지 이미지로 처리되며 원본 메타데이터는 유지하지 않습니다.

## GitHub Pages

`main` 브랜치에 소스를 올린 뒤 저장소 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택하세요. `.github/workflows/pages.yml`이 검증 후 정적 파일 4개만 배포합니다. 최초 설정 후 Actions에서 `Deploy GitHub Pages`를 실행할 수 있습니다.

예상 주소: https://mt0gn.github.io/cutcut/ (Pages가 활성화되고 배포가 성공한 뒤 사용 가능합니다.)

## 검증

`npm test`는 간격 보정, 연속 자르기, 원본 내 배치, 이미지 cover 계산, 사진 묶음의 출력 순서 및 ZIP 구조를 검사합니다. `npm run check`는 JavaScript 구문을 검사합니다.
